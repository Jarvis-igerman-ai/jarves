- Fixed: project manager git commands no longer run commands that the repository's own (agent-writable) git config names: filter drivers (clean, smudge, process), merge drivers, diff commands, signing programs, credential helpers (also URL-scoped), ssh/askpass/pager/editor/proxy/alternate-refs settings, and remote upload/receive-pack and vcs helpers set at repository scope are overridden on JARVES git calls; the owner's global and system settings stay. Per-name drivers (`filter.<x>.*`, `merge.<x>.driver`, `diff.<x>.*`) are found by reading the config right before each call, so an agent that changes the config between that read and git's own read is not covered (accepted risk, P1 #1483). Submodule recursion is turned off, so a filter in a submodule's own config does not run; repository-scope git-lfs or merge-driver settings must move to the global config (projects guide). Auto-maintenance (`maintenance run --auto` / `gc --auto`, which can run `gc.recentObjectsHook`) is turned off and fixed-name command settings (ssh, askpass, pager, editor, proxy, alternate refs, credential helper) are blanked on every JARVES git call; a repository-scope conditional include (`includeIf`) or config hook (`hook.<name>.*`) stops the command: an include can match only inside a child git such as the checkout of `worktree add`, and a config hook has no safe neutral value on newer git. The review diff uses git's own diff only (`--no-ext-diff --no-textconv`), so a diff command in the shared config cannot empty it and skip the review (#1390, #1407).
- Fixed: `project ship --apply` shows the exact integration commit in the approval and merges that commit, so a commit added to the integration branch while the prompt is open is not merged; the ship plan commands name the commit too. A git failure is reported as `GIT_ERROR` instead of "no commit to merge"; the merge commit reads `Merge <integration branch> at <commit>` (#1407).
