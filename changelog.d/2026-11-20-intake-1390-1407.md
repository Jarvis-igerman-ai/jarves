- Fixed: project manager git commands no longer run commands named by the repository's own git config, which agents can write (#1390). Repository-scope filter, merge and diff drivers, credential helpers, trailer commands and remote helpers are blanked on each JARVES git call. Signing programs always come from your global or system config, else git's default. ssh, askpass, pager, editor and proxy settings are always blanked. diff, show and log calls never run an external diff or textconv command. Auto-maintenance and submodule recursion are off. A repository-scope `includeIf` or config hook (`hook.<name>`) stops the command. Your global and system settings stay; move a repository-scope git-lfs filter or merge driver to your global config (projects guide). Known gap: a per-name driver changed between JARVES's config read and git's own read is not covered (P1 #1483).
- Fixed: `project ship` names the exact integration commit, and `--apply` merges that commit, so a commit added while the approval is open is not merged; when a merge commit is needed it reads `Merge <branch> at <commit>` (a fast-forward makes none). A git failure is reported as `GIT_ERROR` in both the plan and `--apply`, not as "no commit" (#1407).
