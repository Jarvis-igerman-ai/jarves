- Fixed: projects: an agent could move the shared integration branch (`git update-ref`) so its protected-file changes were never checked. JARVES now records the integration commit itself and diffs, reviews, merges, releases and ships that commit. It merges a task only at the commit it checked, even if another agent moves that task's branch or a re-run check commits, and re-checks protected and out-of-scope files on exactly that commit. Files a check writes are committed and checked for protected and out-of-scope paths before the commit is recorded, so in-scope output still merges. It stops when a branch was moved outside JARVES. A project opened before this fix adopts its integration commit only when that exact commit has no protected changes; a task checked before the fix is asked to retry (#1352).
