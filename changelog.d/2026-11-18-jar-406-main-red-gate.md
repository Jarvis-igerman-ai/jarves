- Fixed: the workflow sync now judges main's CI state by the newest run of the required jarves-checks gate, so a failed nightly Flake detector or `beta` job on the main commit, or a failed attempt that a later run superseded, no longer reports main as red (JAR-406). With no gate run, the previous all-checks rule still applies. On a green main the sync also reads the newest `beta` publish run (success, failure, pending, unknown or none): a failed one raises a `beta_failed` release-health alert, and the autopilot opens a beta-verify task only when that run passed or was skipped (beta publish off). No beta run seen yet counts as pending, since the package workflow starts only after the gate passed; a gate or beta run list longer than one page counts as unknown.
