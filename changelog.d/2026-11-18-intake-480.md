- Fixed: the security-scan tracker (#480) now says what to do for each source GitHub refused: HTTP 401 (set a valid token), 403/404 on alert sources (turn the feature on or give the token read access), 403/404 on workflow runs (give the token Actions read access), 403/404 on other sources (give the token read access), a "Retry note" for 429/5xx and a neutral "Unexpected HTTP" line for other codes such as 410 or 422. Any change in the sources not fully read or their reasons (an HTTP code or another reason such as a boundary test that did not run) rewrites the tracker once, so these lines and the "Sources not fully read" line never go stale; a scan with every source read keeps the old signature.
