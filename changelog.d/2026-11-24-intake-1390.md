- Fixed: project manager git calls no longer run filter, merge-driver, diff-driver or `diff.external` commands named in the repository's shared config (including `include.path` files) or the editors, and never recurse into submodules (#1390). Owner global/system drivers stay active; a repository-level filter that reuses an owner filter's name (e.g. `git lfs install --local`) now stops the call with a message instead of silently passing content through. Behaviour change: any repository-level `merge.<x>.driver`, even a harmless one, now makes JARVES's merge conflict and abort. JARVES's own `git diff/show/log` pass `--no-ext-diff --no-textconv`; `git()` refuses a global option such as `-C` before the subcommand; an unreadable shared config or a git older than 2.26 stops the call. Not covered: a submodule's own config, `gpg.program`, `core.sshCommand`, credential helpers, config-defined hooks, and a key added between the config read and the command.
