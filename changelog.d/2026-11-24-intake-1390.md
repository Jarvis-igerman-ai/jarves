- Fixed: project manager git calls no longer run filter, merge-driver, diff-driver or `diff.external` commands named in the repository's shared config (including `include.path` files) or the editors, never recurse into submodules and never look inside a populated submodule's work tree (that submodule's own config and filters stay unused; gitlink commit changes still show), and `commit_all` leaves gitlinks out of `git add -A` (#1390). Owner global/system drivers stay active; a repository-level filter that reuses an owner filter's name (e.g. `git lfs install --local`) now stops the call with a message instead of silently passing content through. Behaviour change: any repository-level `merge.<x>.driver`, even a harmless one, now makes JARVES's merge conflict and abort. JARVES's own `git diff/show/log` pass `--no-ext-diff --no-textconv`; `git()` refuses any option before the subcommand; an unreadable config or a git older than 2.31 stops every call. Not covered: `gpg.program`, `core.sshCommand`, `core.askPass`, credential helpers, transport commands (`remote.<x>.uploadpack/receivepack`, `ext::` URLs), `core.alternateRefsCommand`, config-defined hooks, and a key added between the config read and the command.
