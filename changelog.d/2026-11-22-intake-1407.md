- Fixed: project manager owner prompts name commits, not branch names: the review command, the merge approval (task commit and integration commit) and the "merged into" event. Approving a merge covers only the commit you were shown; if anything changed after the prompt (a new commit, or files left uncommitted, yours or an agent's), it commits them and asks again, naming the new commit. A re-merge with newer work must have exactly your commit and the integration commit read as parents; a fast-forward no longer asks again. `ship` plans, approves and merges the integration branch's exact commit, so a later commit or a same-named tag is not merged. JARVES git calls no longer run filter, merge or diff drivers, textconv, `diff.external`, config hooks, gpg programs or `gpg.ssh.defaultKeyCommand` set in the project's own `.git/config`, and stop if that config cannot be read; your own global or system value for the same key is kept. If that config changes signing settings, the merge into your branch is not signed (#1407).
