- Fixed: the security-scan tracker (#480) now names the owner action next to each source whose access was refused: HTTP 401 says the scan token is missing, expired or invalid; HTTP 403/404 on Dependabot or secret scanning says to turn the alerts on if they are off and give the scan token read access. Transient errors and skipped sources get no action line. The tracker signature now includes a body-template version and the set of refused sources with their codes, so the tracker is rewritten once for the new text and again whenever access changes (for example 403 to 401, or one source recovering); transient 5xx errors do not change it.
