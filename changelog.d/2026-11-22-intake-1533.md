- Fixed: project manager runs no longer let an agent or a check change the repository's shared git files (`.git/config`, `config.worktree`, `info/attributes`), which could make git run a planted filter or driver for JARVES or later for you (#1533). A change made while agents or checks run is put back, a copy of it is kept as `<name>.jarves-rejected`, and every run active at that moment fails, including the one that wrote it. After the last run, a later change (your own edit, or a process a run left behind) is never reverted, but JARVES refuses project commits and new runs in that repository until you restart JARVES to accept it. Claude Code agents also get edit and write deny rules for the repository's git folder (defence in depth; live enforcement UNVERIFIED). A write between JARVES's check and git's own read is still possible.
