- Fixed: project manager runs no longer let an agent or a check change the repository's shared git files (`.git/config`, `config.worktree`, `info/attributes`, and each worktree's `commondir`/`gitdir`), which could make git run a planted filter or driver for JARVES or later for you (#1533). JARVES reads where each worktree's git folder is once, when it creates the worktree, and its own git commands there use those folders, so a rewritten `.git` pointer to a fake folder is never followed. A change made while agents or checks run is put back, each rejected copy is kept as its own `<name>.jarves-rejected-<number>` file, and every run active at that moment fails, including the one that wrote it. JARVES's own worktree creation and removal update the reference (its new branches no longer get tracking config). After the last run, any other later change (your own edit, or a process a run left behind) is never reverted, but JARVES refuses project commits and new runs in that repository until you restart JARVES to accept it. Claude Code agents also get edit and write deny rules for the repository's git folder (defence in depth; live enforcement UNVERIFIED). A write between JARVES's check and git's own read is still possible.
