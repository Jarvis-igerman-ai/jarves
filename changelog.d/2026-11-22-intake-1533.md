- Fixed: project manager: an agent or check that changes the shared git files JARVES git reads (the repository's `config`, `config.worktree` and `info/attributes`, plus your `~/.gitconfig` and `~/.config/git/config`/`attributes`) fails, and the files are put back (the newest 5 rejected copies are kept; the file mode is kept). After the last run, a change that adds a key git may run (a filter, a driver, a hook, an `include`) stops JARVES git in that repository until restart instead of running it; ordinary edits such as `git remote add` are accepted. JARVES worktrees use the git folders read when they were made, and after a restart an integration worktree that does not point into its own repository is refused (#1533). Not covered: the admin-owned system config and a custom `core.attributesFile` path.
