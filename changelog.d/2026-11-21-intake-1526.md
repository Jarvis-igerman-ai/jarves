- Fixed: when privacy mode is on at Core start, or is switched on later, the plan executor blanks plan text written before it in memory.db (step evidence and error, plan result and note) and keeps only status and error codes (a code must contain "_"). Step rows are scrubbed in transactions of 500 rows, so the database lock is free between them, and the scrub stops if privacy is switched off in the middle; the last transaction blanks the plan rows. Freed space is overwritten and in WAL mode the -wal file is checkpointed and truncated, then secure_delete is set back to its earlier value. A failed batch is rolled back; a failed scrub is tried again after 30 s, doubling up to 15 min, and a checkpoint kept busy by a reader logs PLAN_PRIVACY_CHECKPOINT_BUSY once per incident. A table with more than 2000 step rows is scrubbed in a worker thread (#1526).
