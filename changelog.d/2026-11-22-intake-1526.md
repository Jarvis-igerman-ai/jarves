- Fixed: privacy mode now removes goal plan text written before it was switched on (#1526). At Core start and whenever privacy turns on, the plan executor blanks step evidence and error text and the plan's note and result in one explicit transaction, keeping state, step status and the "N/M steps done." count. In the same transaction, with SQLite secure_delete on, it zero-fills memory.db's free pages and rewrites the two plan tables with the same ids, so text freed earlier (a deleted plan) is overwritten too; then the WAL is truncated. Other tables in memory.db are not rebuilt (no VACUUM), so their rowids never change. None of these steps waits for another process: a locked database or busy WAL is warned once and retried on the next tick.
