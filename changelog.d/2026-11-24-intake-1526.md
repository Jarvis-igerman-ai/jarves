- Fixed: privacy mode now also scrubs goal plan text written before it was switched on (#1526). When privacy is on at Core start, when it turns on, or after tool text was written while it was off (also between two runner ticks), the plan runner erases older step evidence and tool text in step errors, plan notes and results in one memory.db transaction. It keeps only statuses, result codes and JARVES's own fixed reasons. It then compacts memory.db (VACUUM, so free pages from older deletes are rewritten) and truncates the write-ahead log. A busy checkpoint, or any other database error, counts as a failure: it is retried on the next tick, logged once and never stops a plan. New block and failure reasons written in privacy mode get the same reduction.
