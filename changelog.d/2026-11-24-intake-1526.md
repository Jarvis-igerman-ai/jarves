- Fixed: privacy mode now also scrubs goal plan text written before it was switched on (#1526). With privacy on at Core start, after it turns on, or after tool text was stored while it was off, the plan runner erases older step evidence in one memory.db transaction over the two plan tables. That transaction runs in a worker thread on its own short-lived connection, so it never holds the plan store's lock; a failed scrub never stops plans, and a plan write made while the scrub's short write transaction is open waits for it (up to the shared connection's 5 s busy timeout). Stopping the runner waits for a running scrub. Step errors and plan notes keep only JARVES's own fixed reasons, cap notes or a whole result code; other text becomes "failed". A done plan's result keeps its `N. tool: status` lines, built by the same code as a new result. A failed or busy scrub (another writer for more than 0.5 s) is retried after a backoff (2 s doubling to 300 s) and logged once per outage. secure_delete is on for that connection only. Not scrubbed: a plan's title and each step's tool arguments and reason, which are the owner's plan and not tool output, so text typed there stays in memory.db. Older copies already in the write-ahead log or free pages are not forced out (no checkpoint, no VACUUM).
