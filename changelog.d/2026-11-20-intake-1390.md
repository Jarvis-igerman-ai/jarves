- Fixed: the project manager's own git calls no longer run commands named in a repository's shared git config (#1390). Filters, merge drivers, ssh, editor, pager, askpass, gpg (including the ssh default-key command), trailer and config-hook programs set at repository scope (or in a file it includes) are replaced by your global/system value or git's safe default. When the repository adds a credential helper, the helper list is cleared and only your own helpers run. External diff and textconv are off for diff/show/log/blame. Pushes and fetches use git's own pack programs and only the https and ssh transports, so a remote, `pushurl` or `insteadOf` in the repository config can no longer point a push at a local repository (whose hooks would run), an `ext::` command, a remote helper or `core.gitProxy`. A repository config git cannot read now stops the call instead of reading as empty output. A filter that only the repository config sets is off for JARVES runs; if that config also marks it required (e.g. `git lfs install --local`), JARVES stops with a message instead of committing unfiltered files: set the filter in your global git config.
