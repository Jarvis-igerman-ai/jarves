- Fixed: on Linux a project's check command and the release command run in their own user and mount namespace (kernel 5.12+). There the whole file system is read-only except the run's worktree (not its `.git` pointer) and empty private `/tmp`, `/var/tmp`, `/dev/shm`, `/run/user/<uid>` and `~/.cache` folders. Task code therefore cannot change or rename the repository's shared git files or their parent folders, or plant code in the owner's home, also from a process it leaves running. A check also has no network (loopback only). A release keeps the network and may still write git objects, refs and tags. An agent no longer runs the check command directly: it runs it through a `jarves-check` script that applies the same confinement. If a run cannot be confined on a machine that supports it, the run fails. Where user namespaces are off, and on Windows and macOS (#1665), checks run as before and JARVES logs that once. (#1592, JAR-746)
