- Fixed: on Linux a project's check command, the release command and an agent allowed to run the check now run in their own user and mount namespace where the repository's shared git files (config, hooks, info, `commondir`) and every worktree's `.git` pointer are read-only, also for a process left running after the run. An agent's `git add`/`commit` and a release's `git tag` still work. If the namespace cannot be set up for a run, that run fails and its command never runs. Where user namespaces are off, and on Windows and macOS (#1665), checks run as before and JARVES logs that once. `~/.gitconfig` and other repositories are not covered. (#1592, JAR-746)
