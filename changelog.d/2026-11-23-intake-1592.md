- Fixed: projectmgr: a project's check command (run by JARVES, or by an agent through its check rule) can no longer leave behind something the owner's own git later runs. Guarded: the shared `.git/config`, `config.worktree`, `info/attributes`, the `.git/hooks/` folder and the worktree's `.git` pointer. They are read when the run starts; anything changed is put back, a copy of the rejected text is kept in `.git/jarves-rejected/` (one file per incident, at most 1 MiB each, the newest 20 kept), and the run fails. The snapshot is never re-taken during a run, so a write timed to land during a JARVES worktree call is still undone. A run whose git config cannot be found, or whose guarded file is already over 1 MiB, is refused. On Linux every process the run started, a detached one too, is killed before the comparison. Limits: on Windows and macOS a detached process left by the run can still write after it ends (#1665); `~/.gitconfig` and config include targets are not watched; a change undone before the run ends is not seen; any change during a run is reverted, the owner's own `git config` in that repository included (#1592).
