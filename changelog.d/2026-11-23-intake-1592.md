- Fixed: on Linux a project's check command now runs in its own user, mount, PID and network namespaces (kernel 5.12+). This also applies when an agent runs the check: it does so through a `jarves-check` script. Inside, the whole file system is read-only except the run's worktree (not its `.git` pointer). `/tmp`, `/var/tmp`, `/dev/shm`, `/run` and `~/.cache` are empty private folders, and every other bound unix socket path is covered. The check has no network, and it cannot see, trace or signal any process outside. Every process it starts ends with it. So task code can neither change nor rename the repository's shared git files or their folders, nor plant code in the owner's home or reach the owner's daemons. If a run cannot be confined on a machine that supports it, the run fails. Where user namespaces are blocked, and on Windows and macOS (#1665), checks run as before and JARVES logs that once. The owner's release command is not confined; that scope is the owner's decision. (#1592, JAR-746)
