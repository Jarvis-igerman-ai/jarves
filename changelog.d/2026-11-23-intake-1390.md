- Fixed: projectmgr git calls refuse to run while the repository's own config, a file it includes, or the config of any submodule in the shared `.git/modules` (nested ones too) names a command git would run: filter and merge drivers, diff commands, `diff.external`, `interactive.diffFilter`, editors, `core.sshCommand`, gpg programs and `gpg.*.defaultKeyCommand`, non-empty credential helpers, a `!command` `submodule.*.update`, `core.alternateRefsCommand`, browser, `help.browser`, `instaweb.*` and man viewer commands, config-defined hooks and `includeIf` (#1390). Pagers, an empty `credential.helper` and `submodule.*.update=checkout/rebase/merge/none` are accepted. Every call also sets `protocol.ext.allow=never` (no `ext::` command transport) and refuses `-C`/`--git-dir`/`--work-tree` anywhere before the subcommand. A refusal raises `GitError` for `check=True`; a `check=False` call gets a failed result (code 128) as before, so `merge_in` reports "not merged". The owner's global config is not checked; a repository with such a key set locally (for example `git lfs install --local`) is refused until it is removed. A key written between JARVES's config read and git's own read is detected by a second read after the call, not prevented (#1655). Each call starts four extra git processes, plus two per submodule config file (about 8 ms per call on Linux; Windows not measured).
