- Fixed: projectmgr git calls refuse to run while the repository's own config, a file it includes, or (recursively) the config of any populated gitlink git would enter names a command git would run: filter and merge drivers, diff commands, `diff.external`, `interactive.diffFilter`, editors, `core.sshCommand`, gpg programs and `gpg.*.defaultKeyCommand`, non-empty credential helpers, a `!command` `submodule.*.update`, `core.alternateRefsCommand`, browser, `help.browser`, `instaweb.*` and man viewer commands, config-defined hooks, `gc.recentObjectsHook`, an alias that starts with `!` or with a global option such as `-c`, and `includeIf` (#1390). Pagers, a plain alias such as `alias.st=status --short`, an empty `credential.helper` and `submodule.*.update=checkout/rebase/merge/none` are accepted. Every call also sets `protocol.ext.allow=never` (no `ext::` command transport) sets `submodule.recurse=false`, `fetch.recurseSubmodules=false` and `push.recurseSubmodules=no`, and refuses `-C`/`--git-dir`/`--work-tree` anywhere before the subcommand. A populated gitlink is a submodule in `.git/modules` or in a linked worktree's `.git/worktrees/<wt>/modules`, a nested repository whose `.git` folder sits in the work tree, or a `.git` file whose `gitdir:` points anywhere; a gitlink list git cannot read is refused (fail closed). A refusal raises `GitError` for `check=True`; a `check=False` call gets a failed result (code 128) as before, so `merge_in` reports "not merged". The owner's global config is not checked; a repository with such a key set locally (for example `git lfs install --local`) is refused until it is removed. A key written between JARVES's config read and git's own read is detected by a second read after the call, which fails the call and says the call already ran; it is not prevented (#1655). Each call starts six extra git processes (three before and three after), plus three per populated gitlink: about 12 ms per call in a 2,000-file repository on Linux; Windows not measured.
