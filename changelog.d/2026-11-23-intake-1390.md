- Fixed: projectmgr git calls refuse to run while the repository's own config (or a file it includes) names a command git would run: filter and merge drivers, diff commands, `diff.external`, `interactive.diffFilter`, editors, `core.sshCommand`, gpg programs and `gpg.*.defaultKeyCommand`, non-empty credential helpers, a `!command` `submodule.*.update`, `core.alternateRefsCommand`, browser and man viewer commands, config-defined hooks and `includeIf` (#1390). Pagers, an empty `credential.helper` and `submodule.*.update=checkout/rebase/merge/none` are accepted. Every call also sets `protocol.ext.allow=never` (no `ext::` command transport) and refuses `-C`/`--git-dir`/`--work-tree` anywhere before the subcommand, so git always works in the folder that was checked. The owner's global config is not checked; a repository with such a key set locally (for example `git lfs install --local`) is refused until it is removed. A key written between JARVES's config read and git's own read is not prevented: a second read after the call detects it and fails the call. Each call starts two extra `git config` processes; `is_repo` answers False and `repo_state` returns empty values for a refused repository.
