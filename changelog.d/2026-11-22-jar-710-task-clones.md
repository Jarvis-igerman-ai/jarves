- Fixed: security #1599 / #1390: each project-manager task now runs in its own clone of your repository (`git clone --shared`, its own `.git`, no remote) instead of a `git worktree` that shares your repository's `.git`. JARVES never runs git with the task folder's `.git`. It commits the folder's files through your repository's git folder with a private index, merges with `git merge-tree` in your repository, and reads every diff from the task branch there. So filters, merge drivers, fsmonitor, hooks and config hooks that an agent writes into its own git settings never run for JARVES, and there is no config read that could race an agent's write. The task branch in your repository is the record; after each JARVES commit or merge the folder's own branch and index are moved to match it (written as text, skipped when anything there is a link), so `git status` in the folder stays clean. Cleanup of a task folder never makes a file writable through a link (an agent's link to a file outside its folder is left alone, and what cannot be removed is logged), and task folders state that they need git 2.38 or later before a task folder is made, instead of failing with an unknown option. A merge whose task branch moved meanwhile puts the folder's files back and says why.
