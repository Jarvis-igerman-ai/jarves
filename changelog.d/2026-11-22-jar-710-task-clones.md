- Fixed: security #1599 / #1390: each project-manager task now runs in its own clone of your repository (`git clone --shared`, its own `.git`, no remote) instead of a `git worktree` that shares your repository's `.git`. JARVES never runs git with the task folder's `.git`. It commits the folder's files through your repository's git folder with a private index, merges with `git merge-tree` in your repository, and reads every diff from the task branch there. So filters, merge drivers, fsmonitor, hooks and config hooks that an agent writes into its own git settings never run for JARVES, and there is no config read that could race an agent's write. The task folder's own git history is a scratch copy; the task branch in your repository is the record. Cleanup of a task folder never makes a file writable through a link (an agent's link to a file outside its folder is left alone, and what cannot be removed is logged), and task folders state that they need git 2.38 or later instead of failing with an unknown option.
