- Fixed: security P3 list #206. Privacy mode: the phone resend ledger (`continuity.db`) keeps only numbers, flags and a fixed code/state of an answer, never its words. Rows written while privacy was off are blanked at the next Core start, or at the first ledger write with privacy on after a write made with it off (not before every write), and freed pages inside `continuity.db` are overwritten (`secure_delete`); the short-lived rollback journal of that write is deleted, not overwritten. A privacy-mode resend of an error keeps its fixed code and message, or gets a defined "answer not kept" message; a resent success answer gets no error code added. Rewording a confirmed preference on the phone now sets it back to proposed (a confirm racing the edit cannot make the new words active; if the row keeps changing, nothing is saved and the phone gets a 409 `PREF_CHANGED` "try again" message in English and Hebrew). The phone guide says the `status` permission shows whether the computer microphone is in use; the project-manager guide says the check command runs agent code without a sandbox. Not changed: plan step evidence in privacy mode, and the ledger is not cleaned at the moment privacy is switched on (#1395).
