- Fixed: security hardening (#206). With privacy mode on, the phone resend ledger (`continuity.db`) keeps only the allowlisted keys `ok`, `n`, `pref`, `goal`, `plan` (numbers or flags) and an UPPER_CASE `code`, never answer text. Older rows are rewritten when the ledger is opened (a Core start), and on a later read or write while privacy is on if a privacy-off write may have left words: each body is parsed, so a body is not trusted by its first characters. Expired rows are deleted at the same points once a row can have expired; a ledger with nothing to change is not scanned or locked again. Freed database pages are overwritten (`secure_delete`) and the ledger uses the rollback journal (no WAL file). A resend answered from such a row gets the code `NOT_KEPT` (a replaced code stays in `code_kept`) and a defined Hebrew/English message instead of a blank answer. Plan steps keep no tool output text in privacy mode (the error keeps only the code). A preference reworded on the phone goes back to proposed and needs a new confirm, with guarded database statements, so a confirm that lands during the edit cannot keep it confirmed, and the log names the update that really ran. A confirm sent for the old wording that arrives after the edit is not covered (#1514). The phone and project-manager guides now say that the `status` permission shows whether the computer microphone is in use, and that the project check command runs agent code without a sandbox.
