- Fixed: security hardening (#206). With privacy mode on, the phone resend ledger (`continuity.db`) now keeps only numbers, flags and an error code, never answer text, under plain identifier keys only. Rows written before privacy was switched on lose their text, and expired rows are deleted, when the ledger is opened (a Core start), read or written while privacy is on. Freed database pages are overwritten (`secure_delete`) and the ledger uses the rollback journal (no WAL file); the journal file of a scrub may still hold old pages on disk after it is deleted. A resend answered from such a row gets the code `NOT_KEPT` (the original code stays in `code_kept`) and a defined Hebrew/English message instead of a blank answer; a chat resend puts the phone's language (`lang`) in `reply`. A preference reworded on the phone goes back to proposed and needs a new confirm, also when a confirm lands between the edit's read and its write. A confirm sent for the old wording that arrives after the edit is not covered yet (#1514). The phone and project-manager guides now say that the `status` permission shows whether the computer microphone is in use, and that the project check command runs agent code without a sandbox.
