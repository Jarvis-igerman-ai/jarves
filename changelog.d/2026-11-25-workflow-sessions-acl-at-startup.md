- Fixed: on Windows the workflow server now applies the owner-only ACL to an existing sessions.json when it loads it at startup; before, a file written before the #824 fix kept the inherited folder ACL until the next login rewrote it. A failed attempt to tighten an existing access.token or sessions.json is now retried on the next load, at most 3 times per file and process, instead of being marked done; when every attempt failed, the last one to finish logs one error, and none is logged if a concurrent attempt succeeded. A sessions.json whose ACL denies reading its attributes no longer stops the server from starting (JAR-824, JAR-260 reopened).
