- Fixed: projectmgr `forge.push_branch` (owner-identity push) now pushes to a pinned `https://github.com/<owner>/<repo>.git` given by the caller (a strict `owner/repo`, no `.git`), from a throw-away repository that reads no repository, global, XDG or system git config, so planted `url.*.insteadOf`/`pushInsteadOf`, `http.proxy`, `http.sslVerify=false` or URL-specific `http.<url>.*` keys cannot redirect it or weaken TLS; git older than 2.32 (which ignores `GIT_CONFIG_GLOBAL`) is refused; only the system `http.sslBackend` (schannel/openssl) is carried over, plus, with openssl, a system `http.sslCAInfo` that is a file inside the git install; the temporary repository is pinned with `GIT_DIR` and the push is refused if, as the push itself reads it, any config value outside the command line is a key besides the exact ones `git init --bare` writes, or the repository holds any entry `git init --bare` does not make (a planted `.git` or `commondir`), and sha256 repositories keep their object format (#1595).
