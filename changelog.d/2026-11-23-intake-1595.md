- Fixed: projectmgr `forge.push_branch` (owner-identity push) now pushes to a pinned `https://github.com/<owner>/<repo>.git` given by the caller (a strict `owner/repo`, no `.git`), from a throw-away repository that reads no repository, global or XDG git config, so planted `url.*.insteadOf`/`pushInsteadOf`, `http.proxy`, `http.sslVerify=false` or URL-specific `http.<url>.*` keys cannot redirect it or weaken TLS; only the system `http.sslBackend` (schannel/openssl) is carried over, plus, with openssl, a system `http.sslCAInfo` that is a file inside the git install; the push is refused if its temporary repository config holds any key besides the exact ones `git init --bare` writes (so a planted `core.askPass`, `core.sshCommand` or `core.gitProxy` is refused), and sha256 repositories keep their object format (#1595).
