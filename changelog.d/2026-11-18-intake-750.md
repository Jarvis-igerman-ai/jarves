- Fixed: workflow dashboard answer unlock (#750): the unlock.json record is now an HMAC under an X25519 secret shared with the running dashboard server's in-memory key (public half in unlock.pub), so an agent that reads the workflow home (access.token, unlock.json) can no longer test the 4-digit code offline and post answers over HTTP; `jarvis workflow unlock` and `open` now refuse to show a code when the dashboard server is not running (they ask the dashboard's /health for its public key and compare it with unlock.pub, so a stale file with another program on the port gives no code, and a clean stop removes its unlock.pub). A server that fails to start closes the workflow.db it opened, and a stopping server renames unlock.pub away before it checks the key, so it never removes a key another server wrote at the same moment. A failed unlock.pub cleanup on stop no longer leaves the server socket or workflow.db open.
