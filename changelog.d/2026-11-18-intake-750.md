- Fixed: the dashboard unlock code can no longer be checked offline from the workflow files (#750). Each dashboard keeps a private key only in memory and publishes its public half; `unlock.json` now holds an ephemeral key and a keyed tag instead of a scrypt hash, so only the running dashboard can verify a code. `jarvis workflow unlock` exits 4 (shown in `--help`, distinct from usage error 2; `open` prints a hint) when no dashboard listens on the port or its key is not published, so a stopped dashboard gets no code; a stopped dashboard removes its published key. Without `--port`, `unlock` uses the port the published key records (still checked as listening). A JSON `true`/`false` port counts as no port, and closing a dashboard twice withdraws its key and closes its store once. `unlock.json` is now replaced atomically (temp file + `os.replace`), like `unlock_pub.json`. Known limit: an agent that runs code as the owner's OS user can still mint a code.
