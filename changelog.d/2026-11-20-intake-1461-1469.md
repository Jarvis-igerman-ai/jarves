- Fixed: projectmgr no longer merges a task commit that no check or review saw (#1461). The check and review stages record the task commit. Each later check, the review and the merge block when the task branch has moved since then, even if the merge re-runs the check, unless you approved that exact commit. Edits left uncommitted after a recorded check or review are never merged: they are saved under a `refs/jarves/dropped/...` ref, which the warning names, and removed from the task folder. The merge fast-forwards that exact commit instead of the branch name. The owner's merge approval binds to the commit its prompt named. If the commit moves before the merge, you are asked again, and the prompt says when the commit is not the checked one. The owner's review command, the merge approval text, the "merged into" event and the agent card now name the integration commit instead of only the branch. Dead adopt-check code in the owner work stage is removed (#1469 items 1 and 2).
