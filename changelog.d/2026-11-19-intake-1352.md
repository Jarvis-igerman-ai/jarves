- Fixed: project manager: a task that moves the shared `jarves/p<id>/integration` ref (git update-ref) can no longer hide its protected-file changes. JARVES records the integration commit itself (at open, before the first agent of a project opened by an older version, and after each of its own merges) and diffs, merges, reviews, ships and releases against that commit; when the branch was moved outside JARVES the task is blocked (also when it moves during the merge or while a release waits for approval) and ship (apply and preview) answers `MOVED`, with the `git reset --hard <commit>` line that restores the branch. New task worktrees start from the recorded commit, and the record is written before the fast-forward, so a database error merges nothing. Protected, symlink and out-of-scope files are re-checked on the exact commit fast-forwarded (#1352).
