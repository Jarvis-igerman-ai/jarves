- Fixed: the project manager no longer merges a task commit that nobody checked. It records the commit it scope-checked and checked, merges that exact commit, and blocks the check or the merge when another agent moved the task branch or left uncommitted changes to tracked files in its folder in between. Untracked files, such as a check's `.coverage`, are never merged and do not block. An edit made at the merge approval goes through the same scope and protected-path rules and runs the project check again before it merges. When the integration branch moved, checking the merge needs git 2.38 or newer, and older git now gets its own reason (#1461).
