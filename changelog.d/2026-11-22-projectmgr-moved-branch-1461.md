- Fixed: the project manager no longer merges a task commit that nobody checked. It records the commit it scope-checked and checked, merges that exact commit, and blocks the check or the merge when another agent moved the task branch or left uncommitted changes to tracked files in its folder in between. A retry after such a block runs the work stage again. The check refuses to run when the folder holds untracked files that a previous JARVES check did not leave, because they could change the result without ever being merged. Its own leftovers, such as `.coverage`, are tolerated while unchanged. An edit made at the merge approval goes through the same scope and protected-path rules and runs the project check again before it merges. When the integration branch moved, checking the merge needs git 2.38 or newer, and older git now gets its own reason (#1461).
