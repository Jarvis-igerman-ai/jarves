- Fixed: the project manager no longer merges a task commit that nobody checked. It records the commit it scope-checked and checked, merges that exact commit, and blocks the check or the merge when another agent moved the task branch or left uncommitted changes to tracked files in its folder in between. A retry after such a block runs the work stage again. The check runs in a throw-away checkout of exactly that commit, so untracked or ignored files in the shared task folder (including ones hidden by the shared `info/exclude` or written while the check runs) cannot change a result for content that never merges. An edit made at the merge approval goes through the same scope and protected-path rules (a refused edit is blocked with that reason) and runs the project check again before it merges. A block in a flow with no work stage says to add one instead of retrying. When the integration branch moved, checking the merge needs git 2.38 or newer, and older git now gets its own reason (#1461).
