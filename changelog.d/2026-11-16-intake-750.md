- Fixed: the dashboard unlock code can no longer be checked offline from the workflow files (#750). The running dashboard keeps an X25519 key in memory, publishes only its public key after binding and before listening, and removes it on a clean stop (only while it is still its own). `unlock.json` now holds an ephemeral public key and an HKDF-keyed HMAC tag instead of a 4-digit scrypt hash, so someone who can only read `access.token` and `unlock.json` can just guess online (5 tries). `jarvis workflow unlock` exits 2, and `open` shows no code, when no dashboard listens on the port or no live dashboard holds the key lock (`unlock_pub.lock`, an OS lock the publishing dashboard holds for its whole life). So a key left by a crashed server never yields a dead code, even if another program now uses its old port, and the next dashboard replaces it. A second dashboard of the same home keeps the live dashboard's key, does not remove it when it stops, and takes the key over (retrying every 5 seconds) once the first one stops. A code is issued only for the dashboard on the port recorded with the key, and each refusal says which case applies. Known limit: an agent that can write files in the workflow home or run code as the owner can still create a code.
