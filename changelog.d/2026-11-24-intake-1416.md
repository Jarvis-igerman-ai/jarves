- Fixed: a holder of only the workflow access token can no longer cancel the owner's unlock code with 3 + 2 wrong tries from two windows when the owner has a window that unlocked before (#1416). Such an owner window is remembered across restarts (its stored session may last up to the 1-week unlock; other stored sessions stay capped at 12 h) and keeps its own 3 tries. Token-only windows share 5 tries and are then refused with `shared_exhausted`, while the code stays live for the owner window. A window that has never unlocked, an ended owner window or a damaged stored owner list falls back to the old 5-try cancel.
