- Fixed: projectmgr: while an agent run or check command runs, JARVES guards the git config files git reads: the repository's shared `.git/config`, the owner's global `~/.gitconfig` and XDG `git/config`, and a worktree's `.git`/`commondir`/`gitdir` pointer files. A run that changes one is rejected and the file is restored (or removed again); every JARVES git call restores them first while a run is active, and a file that cannot be restored stops JARVES git instead (#1592). Any change during a run is reverted, the owner's own included: the replaced content is kept in a `<name>.jarves-rejected-*` folder next to the file, named in the rejection and logged as PROJECT_GIT_CONFIG_RESTORED. JARVES's own git calls no longer write config (`branch.autoSetupMerge=false`, `worktree.useRelativePaths=false`). Not guarded: the system config and an owner-set GIT_CONFIG_GLOBAL. The GitHub branch push (`forge.push_branch`, no caller yet) now goes to a pinned `https://github.com/<owner>/<repo>.git` from a private temporary repository with no repository, global or system config (GIT_CONFIG_GLOBAL empty, GIT_CONFIG_NOSYSTEM=1), using only the owner's gh login as credential helper and `http.sslVerify=true` (#1595).
