- Fixed: projects: `ship` names the integration commit in its plan, commands and approval prompt, and merges exactly that commit even if the branch moves after you approve. JARVES's git calls no longer run filter drivers, merge drivers, signing programs or config-defined hooks named in the repository's own git config: filters are skipped (a required filter stops the command), merge drivers become a conflict, `ship` signs with your global or system program, format and key, and hooks never run. JARVES's `diff`, `show`, `log`, `format-patch` and `blame` calls run without external diff or textconv commands. A filter in the repository config marked required (for example Git LFS installed with `--local`, in any form git reads as true) now stops with a message to set it in your global config, and opening such a project shows that message instead of "not a git repository". `ship --apply` always makes a merge commit (`--no-ff`) whose message names the branch and the commit; `ship --apply --yes` needs `--commit SHA` from the plan and refuses (MOVED) when the branch moved since. A filter or merge driver that is also set in your global or system config keeps your own command (#1407).
