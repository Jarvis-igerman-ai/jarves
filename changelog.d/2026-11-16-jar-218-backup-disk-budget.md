- Fixed: beta installs no longer fill the disk with backups (#1016, JAR-218). An install takes ONE verified backup (a checkpoint, not a manual backup) and the updater reuses it as the rollback backup; the next Core start reuses it too when no data changed since. Downloaded installers (`updates/*.exe`) are no longer copied into every backup. New size limit for all backups together (`max_gb`, default 4 GB): the oldest automatic backups and checkpoints go first; manual backups, the newest backup, the rollback backup and a backup being restored are never removed by it. Before writing, a free-space check prunes first and stops with `BACKUP_NO_SPACE` instead of filling the drive. New defaults: keep 5 manual backups (was 10) and 3 checkpoints (was 5); the first prune after updating removes the extra older ones (raise them with `jarvis backup settings --manual 10 --checkpoints 5`). `jarvis backup list` shows the total size; doctor warns when backups are over the limit.
