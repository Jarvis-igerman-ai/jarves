- Fixed: beta installs no longer fill the disk with backups (#1016, JAR-218). An install takes ONE verified backup (a checkpoint, not a manual backup); the updater reuses it as the rollback backup and the next Core start reuses it instead of writing another. New size limit for all backups together (`max_gb`, default 4 GB; oldest removed first, never the newest, the newest automatic one or the rollback backup). Before writing, a free-space check prunes first and stops with `BACKUP_NO_SPACE` instead of filling the drive. Defaults: manual 5 (was 10), checkpoints 3 (was 5). `jarvis backup settings --manual N --checkpoints N --max-gb G`; `jarvis backup list` shows the total size; doctor warns when backups are over the limit.
