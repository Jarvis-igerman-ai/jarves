- Fixed: project manager task folders now have their own private `.git` (a clone of the task branch with no remote and no hard links into your repository's objects). JARVES runs its git for a task folder through your repository's worktree entry (`GIT_DIR`/`GIT_WORK_TREE`), which it finds from the repository path it recorded, never from a file in or next to the folder. A filter, merge driver or hook that the agent's plain `git` writes in its folder therefore no longer reaches JARVES's git (#1599). Not covered: an agent with arbitrary file or process access, which can still write your repository's `.git` by path; the `.git` check is check-then-run. The owner's review command now reads `git -C <your repository> diff <commit>...<task commit>`; the folder's own git is informational and does not follow JARVES's commits. A task folder from an older install, or one whose `.git` was replaced by a link, is refused until its next stage adopts it.
