- Fixed: project manager task folders now have their own private `.git` (a local clone of the task branch, no remote), and JARVES runs its git for a task folder through the owner repository's worktree entry (`GIT_DIR`/`GIT_WORK_TREE`), so a filter, merge driver or hook an agent's git writes in the folder never reaches JARVES's git and the config read-then-run race of #1599 is gone. The owner's review command now reads `git -C <your repository> diff <commit>...<task commit>`; the folder's own git is informational and does not follow JARVES's commits. A task folder from an older install is adopted on its next stage; until then JARVES refuses to run git there (#1599).
