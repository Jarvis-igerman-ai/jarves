- Fixed: security hardening #1622: the project manager now runs the GitHub CLI (`gh`) in a fresh empty folder outside the project repository (with GIT_CEILING_DIRECTORIES set), so gh's own git reads no longer see the project's agent-writable git config such as a planted `remote.origin.url`, `url.*.insteadOf` or `core.fsmonitor`. Issue list, pull request create and pull request checks now take an explicit owner/repo, checked against a strict pattern and passed to gh as `--repo`; an empty or malformed owner/repo is refused before gh runs (a trailing newline included). A temporary folder that cannot be removed after the call (Windows: still in use) no longer turns a successful gh call into an error.
