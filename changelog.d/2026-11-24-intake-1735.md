- Fixed: the flaky CI test `test_approvals_hidden_beat_browser.py::test_tab_going_hidden_sends_a_hidden_beat_at_once` (#1735). The approvals page sends two visible `/api/approvals` beats on load and renders on one of them. The test took its marker baseline while the other could still be in flight, and that late beat then rewrote the marker after the hidden beat (CI: 0.09 s past the baseline instead of 75 s). The test now counts the page's own `/api/approvals` fetches and takes the baseline only when none is in flight. A new test, `test_a_late_load_beat_cannot_overwrite_the_hidden_beat`, reproduces that order every time by having the server hold one load beat back. Test-only change: the product code is unchanged.
