- Fixed: project manager pushes (#1722) no longer run commands or follow URLs that the repository's own (agent-writable) git config names, such as `remote.origin.receivepack`/`pushurl`, `url.*.pushInsteadOf` to `ext::`, or `core.sshCommand`: JARVES pushes from a fresh bare repository it creates, which reads the project's objects but not its config, so only your system and global git config apply (an `includeIf "gitdir:..."` or `hasconfig:remote.*.url:` section of yours no longer matches, so a per-folder SSH key or account chosen that way is not used for these pushes). The push goes only to a github.com https/ssh origin URL (no `ext::`, local path, option, or user/token in the URL; owner and repo names start with a letter, digit or `_`), removes its temporary repository (a removal error, such as a file Windows still holds, is logged, not reported as a failed push), then sets `origin/<branch>` locally (best effort: a failure there is logged, not reported as a failed push; no hook runs there). `jarvis project github` now reports a git older than 2.31 instead of failing later. A shallow clone is refused with a clear message (run `git fetch --unshallow`).
