- Fixed: the autopilot policy now refuses a `worker_allowed_tools` override that could let a worker rewrite `autopilot.json`. Refused: a rule naming the file, and any Bash rule whose first command word is not on an allowlist. The word must use plain characters only (no quote, `$`, backtick, `=`, wildcard, brace, `[` or `~`). Allowed words: a short set of read-only tools named without a path (`ls`, `grep`, `head`, `tail`, `wc`, `diff`, ...), `<python> -m pytest`, git with a fixed subcommand and no `-c`/`--config`/`--upload-pack`/`--receive-pack`/`--exec`, and `gh pr|issue|run`. No shell operators may follow the word. An existing override with a now-refused rule makes the policy file invalid, so autopilot fails closed until the owner edits it. Accepted residual: the pytest and git forms can still run code a worker writes into the repository (conftest/plugins, git hooks, repo config, .gitattributes). (#932)
