# V4.5 workstream D: camera usability, first safe slice (branch feat/camera-ux, no PR yet)

Asked: one Camera section with an honest state, a Test camera action that separates a device probe from a frame test, a timed
local preview with a countdown and Stop, spoken phrases mapped to the existing vision tools, a clear local-only / sent-to-provider
line, guide, CLI parity, features row. Built on the existing CameraService / CameraSkill (nothing replaced).

## What changed

- `camera/ux.py`: `view()` (state Off / Available / Previewing / Capturing / Sending to AI / Busy / Error from the REAL sensor state; enabled-only is "Available", never "on"), `probe_test()` (lists devices, opens nothing), `frame_test()` (opens the sensor once, reads ONE still into RAM, measures size / brightness / blur hint / time to first frame, drops it, closes the sensor; never sent, never saved, never shown), error catalog (HE + EN, what happened + one next step) for every Refusal / CameraUnavailable code.
- `camera/service.py`: `sending`, `last_result`, `last_error`, `record_result()`; `look()` records its outcome (no pixels). `camera/switches.py`: `Switches.enabled()`.
- Link: `camera.status` / `camera.test {mode: probe|frame}` (cli role only; replies `camera.view`) in `link.py`, `app.py`, `camera/wire.py`. Dashboard routes `GET /api/camera/status`, `POST /api/camera/test` (`camera/surface.py`; test is local-computer only, Core stopped = sensorless view). Preview reuses the existing `/api/camera/preview` (5 s lease, 60 s hard cap).
- Dashboard page `Camera` (`pages.d/camera.toml`, `dashboard_static/camera.js`): status pill + plain sentence, device, sensor open/closed, picture local vs sent line, last request with time, actionable error box, two separate test buttons, 20 s preview with visible countdown and full-width Stop (44 px targets), RTL via the existing i18n. 47 Hebrew catalog texts through `catalog_add.py` (part `2026-10-24-camera-ux.json`).
- `jarvis camera [status | probe | test-frame]` (`camera/cli.py`, registered via `plugins.d/camera_ux.toml`); `python -m jarves.camera` unchanged. cli_parity `camera` entries now point to `jarvis camera`.
- Voice: `camera_describe` tool description now names "מה אתה רואה / what do you see / מה אני מחזיק", read-only, never on its own, tell the user the one next step on failure.
- Guide `camera.toml` (steps for the page, test, preview, privacy line, 2 problems, EN + HE); features row `camera` evidence updated, status stays `implemented_unverified`.

## Privacy review notes

- Enabling never opens a sensor (test: switch on, 3 ticks, `opened == 0`). Probe opens nothing (test). Frame test: vision `ask` fails the test if called; not counted as a cloud photo; frame dropped; sensor closed.
- Provider send only inside `CameraService.look()` (unchanged path: one still, store=false, daily cap). `data_flow` is `sending_to_provider` only while that call runs.
- No new retention: result records hold kind/code/time/size/hints, no pixels. Preview frames stay RAM-only on the local link; the page removes the `<img>` src on Stop / leaving the page.
- Phones (device principal) get 403 for the test route and for preview (existing). Messages are cli-role only, not face.
