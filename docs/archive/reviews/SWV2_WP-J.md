## Key decisions

- **Switches:** `camera`, `face_recognition`, `camera_when_away`, all default OFF, registered with `jarves.features`
  (WP-I) via the described interface `register(id, title_he, title_en, default_enabled, probe, risk)` / `active(id)`.
  WP-I's module did not exist on any branch yet, so `camera/switches.py` falls back to `LocalSwitches` (same
  interface, memory.db `feature:<id>`), switchable with `python -m jarves.camera on|off <id>`. A failing switch
  backend counts as OFF.
- **Probe never opens the sensor:** picamera2 global camera list; Windows `cfgmgr32` present video-camera interfaces
  (2 ms; found the 2 webcams on this PC without opening them); Linux `/sys/class/video4linux` minus Pi ISP nodes.
  First probe runs in a worker thread; before it, the camera counts as unavailable.
- **Vision through the existing backend path:** `VisionRunner` subclasses `tasks.ResearchRunner` (Responses, stream,
  store=false, budget reserve/commit, BackendTrace logs) with an `input_image` part and no tools.
- **Library:** OpenCV YuNet + SFace (one dependency, Pi 5 aarch64 wheels, MIT/Apache). OpenCV 5.0 dropped Haar
  cascades, so YuNet is bundled instead of relying on a fallback. SFace (38 MB) is an opt-in manual download.
- **Consent:** `camera_enroll` checks switches/models first (no pointless consent prompt), then asks the person on
  screen, then needs exactly one face in all 3 samples. Delete always works.
- **Untrusted image text:** vision rules + `untrusted: true` + a 60 s taint window in which model-called
  action/destructive tools need on-screen approval (`install_taint_guard`, wraps `registry.call` per instance).

## Integration hooks (files owned by others)

- `core/src/jarves/app.py` (3 small hooks): after `GodotLink(...)`: `self.camera = camera_wire.attach(self)`; in
  `stop()` after `registry.drain()`: `await self.camera.stop()`; in `on_message` INBOUND branch:
  `presence.changed` -> `self.camera.external_presence(...)`.
- `core/src/jarves/config.py`: `CameraConfig` class + `camera` field on `Config`.
- `core/pyproject.toml` / `uv.lock`: `camera` optional extra.
- WP-I: when `jarves.features` lands, check its `register` signature matches (positional
  `id, title_he, title_en, default_enabled, probe, risk`; probe returns `(available: bool, detail: str)`), and that
  `active(id)` = enabled AND available. `Switches` picks it up automatically.
- WP-B dashboard: health component `camera` (ok/disabled/unavailable + action) is set; switch UI is WP-I's.
- `workspace/TOOLS.md` is regenerated by `camera/wire.py` after the camera Skill registers (it is generated in
  app.py before the hook runs).
