### 1. Approve/Deny order differs between surfaces (Tier R)
- Desktop renders Approve then Deny: `core/src/jarves/dashboard_static/approvals.js:52-53`.
- Phone puts Deny first and Approve at the inline end: `mobile/m_theme.css:304-305`, `mobile/app.js:338`.
- Result: in Hebrew, Approve is on the right on desktop and on the left on the phone. English mirrors this.
- Proposal: pick one order everywhere. Recommended: the phone's, Deny first, since it was the deliberate choice in #509. This touches approvals, so it needs an owner decision and a `no-automerge` PR.

### 2. Checks miss overlap and inner clipping
- `core/tools/all_pages_rules.js:153-168` only tests whether an element leaves the viewport sideways, and only in `#main` and `.appbar`.
- `core/tests/test_mobile_phone_e2e.py` (`PHONE_FIT`, `audit`) tests sideways scroll, 44 px targets and contrast. It excludes `div.jc-log` and others from the shared rules.
- Neither has a rule for findings 3, 4 or 6. See the proposed test below.

### 3. Quiet-hours pill overlaps the conversation
- Evidence: `03-chat-he-light.png` (covers the first line), `05-chat-approval-he-light.png` (touches the code card).
- Those shots show 22:01, inside quiet hours. A daytime render will not show the pill, so the render must force that state.
- Cause not established. The rendered layout of `.jc-bar` / `.jc-status` needs inspecting (`mobile/m_theme.css`, `chatview.js:217`).

### 4. Connection dot halo clipped
- `.bar .pill` has `overflow: hidden` and no padding, while its dot draws a 3 px `box-shadow` (`mobile/m_theme.css`, `.bar .pill` rules). Visible in `06-approvals-he-light.png`.
- Fix: small inline padding on the pill, or an inset halo.

### 5. Composer focus indicator
- `#tab-chat .jc-in:focus-visible { outline: none; }` (`mobile/m_theme.css:348`). The replacement on `.jc-form:focus-within` only shifts the border colour slightly and keeps the same shadow.
- Fix: a visible 2 px ring on `.jc-form:focus-within`. The contrast of the present state was not measured.

### 6. Dashboard status chips cut off
- `home_he_1440.jpg`: the microphone chip fades to a partial word. `home_he_390.jpg`: the bottom usage strip is cut at the screen edge ("AI API").
- Sideways scrolling may be intended, but only `.appbar` is checked for a scroll cue (`all_pages_rules.js:170-173`), not the bottom strip.

### 7. Home is too long and repeats itself
- `home_he_390.jpg` is 3551 px tall, about four 844 px phone screens.
- About 50 capability chips sit on Home. Privacy state appears in two top chips and again in a card, and that card holds the destructive "delete all conversations" and "clear history" buttons.
- Proposal: Home keeps approvals, what is active and what to do next. Move the chip wall to Features, show one privacy chip, and move destructive actions to the privacy settings page with their confirmation unchanged.

### 8. Phone status strip
- `#audioBar` shows three states wrapping to two lines on every tab (`03-chat-he-light.png`, `06-approvals-he-light.png`), although its own CSS comment calls it "one quiet line" (`mobile/m_theme.css:207`).
- Proposal: when nothing is listening, one short "microphones off" line that expands on tap; keep the loud `.hot` state. This is a privacy indicator, so the true state must stay visible and one tap away.

### 9. `/resume` shown as a user message
- The drawer's history button sends `/resume` as a chat command (`mobile/m_shell.js:142`). `05-chat-approval-he-light.png` shows a `/resume` bubble and "no previous conversations" in the chat.
- Proposal: hide command echoes that the UI itself sent, and show the empty result in the drawer.

### 10. Unknown states with no next step
- `home_he_1440.jpg`: four "unknown" chips under "what is active now" while JARVES is not running.
- Proposal: one line saying JARVES is off, with the way to start it, replacing the four chips. This keeps the honest state and adds an action.

### 11. Countdown wording
- "117 ש׳" (`06-approvals-he-light.png`) and "בעוד 120 שנ׳" (`05-chat-approval-he-light.png`). Use one form.

### 12. Navigation size
- `index.html` has 56 `data-page` attributes in 11 groups; about 33 entries are visible in `home_he_1440.jpg`.
- Proposal: a separate owner-led design task; do not bundle it with the fixes above.

## Proposed: automated all-tabs clipping test, EN + HE

**Goal:** every dashboard page and every phone tab, in both languages, fails on visible clipping or overlap.

**Reuse, do not rebuild:** `core/tools/all_pages_check.py` already walks all navigation pages across languages, widths and themes. `core/tests/test_dashboard_a11y.py` runs it with Hebrew at phone width and English at desktop width. `all_pages_check.py` does not visit the phone app at `/m/`; `test_mobile_phone_e2e.py` has the pairing and tab helpers.

**Add three rules to `all_pages_rules.js`:**
1. `clipped-text`: visible text where `scrollWidth > clientWidth` under `overflow: hidden`, without an ellipsis and a title.
2. `overlap`: sibling text or control boxes that intersect, sampled with `elementFromPoint`, excluding overlays and fixed layers.
3. `scroll-cue`: extend the existing check beyond `.appbar` to the bottom strip.

**Matrix:** dashboard pages and phone tabs (chat, approvals, voice, health, home, drawer) x EN/HE x 390 and 360 px, plus 1440 px for the dashboard.

**States that must be forced:** quiet hours on (finding 3), a waiting approval, long unbroken text, Core off. Use a fixed fake state rather than the clock, because tests must be clock-free.

**Rollout:** report-only first, list existing hits with an owner, then make it blocking. Do not exclude `div.jc-log` from the overlap rule, because finding 3 happens there.

**Cost/benefit:** M, 1-2 days. Runtime is the main risk, so run the full matrix nightly and a small set on PRs. Overlap heuristics can give false positives, hence report-only first. CI workflow edits, if needed, are Tier R; the rules and tests are not.
