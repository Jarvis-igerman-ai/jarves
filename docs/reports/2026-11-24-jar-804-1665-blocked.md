# JAR-804: #1665 is blocked on #1592 (no guard on main to protect)

**Verdict: blocked, no source code changed.** #1665 asks that, on Windows and macOS, a detached
process left by a check run cannot write the shared git files *after the guard closes*. That guard is
not on main, so there is nothing for this ticket to harden.

## Evidence (checked 2026-11-24, origin/main `d1018f1`)
- #1665 names `projectmgr/_reaper.py`, `gitops.config_guard` and the test
  `core/tests/test_projectmgr_1592.py`. None of them exists on main: `ls core/src/jarves/projectmgr`
  has no `_reaper.py` or `confine.py`, `grep -n config_guard core/src/jarves/projectmgr/*.py` prints
  nothing, and `core/tests` has no `test_projectmgr_1592.py`.
- Both #1592 designs were closed unmerged by the factory after 2 fix rounds and an Opus Doctor round:
  - #1661 (config guard plus Linux subreaper), closed 2026-11-23;
  - #1723 (Linux user/mount/PID namespace confinement), closed 2026-11-24 10:47 UTC, with blocking
    findings R1-R4 still open.
- #1592 itself is open. Its JAR-746 status comment (2026-11-23) asks the owner to decide the
  sandboxing design (OS sandbox, per-call overrides, or a known-issue label).
- On main a check run still runs task code as the owner's user without any guard
  (`gitops.run_check`, `runners.py:110`). That code can write `<common>/config` directly while it runs,
  so a detached process that writes later adds no new route.

## Why this ticket does not ship a Windows job object or macOS scan now
- The fix belongs inside whichever #1592 containment lands. #1661 and #1723 contain the run in
  different ways (subreaper versus PID namespace), and the Windows/macOS part has to match that design.
- This container is Linux. A Windows job object or a macOS process-tree scan cannot fail before and
  pass after here, which this ticket's "done when" requires. UNVERIFIED on both platforms.

Which #1592 containment design is accepted (namespace confinement as in #1723, the config guard as

the chosen design, with the issue's test enabled on those platforms.
