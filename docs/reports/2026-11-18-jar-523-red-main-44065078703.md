# JAR-523: root cause of red main run 44065078703

**Verdict: flaky test (test-side race), not a product regression.** Already fixed on main by JAR-518 (PR #1260, commit 4f450d2); this ticket adds a deterministic regression test.

## What failed
Nightly `jarves-nightly`, job "Flake detector (3x suite, Linux)", commit `85aa2aa`. Passes 1 and 2 were green;
pass 3 failed one test: `tests/test_browser_driver.py::test_a_hung_page_cannot_keep_the_browser_alive_after_stop`
with `assert not True / where True = _pid_alive(85256)`. The log shows `BROWSER_DRIVER_ABANDONED` ("did not stop in time;
killing it"), so the product kill path ran.

## Root cause
The test checked liveness after `release.set()`, which unblocks the driver's event loop so it reaps the killed node driver.
A reap between `os.kill(pid, 0)` and opening `/proc/<pid>/stat` raised `FileNotFoundError`, which the helper treated as
"alive". JAR-518 now decides before releasing and treats a vanished `/proc` entry as dead.

## Reproduction (Linux)
```
git worktree add ../wt85 85aa2aa && cd ../wt85/core && uv sync --frozen --all-extras
export CI=true JARVES_PILOT_NO_SANDBOX=1   # the test sets the second; CI=true allows the no-sandbox fallback as root
for i in $(seq 1 20); do uv run pytest -q -p no:cacheprovider \
  "tests/test_browser_driver.py::test_a_hung_page_cannot_keep_the_browser_alive_after_stop" || echo FAIL; done
```
Results seen (18 Nov 2026, cloud container, Chromium headless shell): at `85aa2aa` 19 passed, 1 failed with the same
`_pid_alive` assertion; at main `fe6d307` 40 of 40 passed. The new test
`test_a_driver_reaped_after_the_kill_probe_counts_as_dead` fails on the `85aa2aa` helper (`assert not True`) and passes on main.
