# JAR-835: why JAR-260 kept reopening, and the re-fix

## Product root cause (unchanged since JAR-824)
`load_sessions()` only read an existing `sessions.json`. A file written before
#824 kept the inherited folder ACL until a sign-in rewrote it, so the #824
acceptance ("owner-only ACL ... at startup") failed on upgraded installs.

## Why three re-fixes (#1752, #1761, #1778) never landed
- Each PR grew in review rounds (retry counters, locks, threads: #1761 reached
  266 lines) and was closed after 2 fix rounds plus a Doctor round.
- #1752: the Windows real-ACL test never finished on CI (pushes cancelled runs).
- #1761: Fast CI died on a runner timeout downloading `setup-uv`; closed red.
- #1778: last verdict COUNCIL with no blocking product finding; closed on two
  test follow-ups (R2, R3) still open.

## This re-fix
The #1778 product change as reviewed (about 8 lines in `server.py`), plus:
- R2: the absolute spelling comes from `os.getcwd()`, not `tmp_path`.
- R3: the real-ACL precondition asserts an inherited `BUILTIN\Users` ACE
  (SID S-1-5-32-545, name resolved locally, so it is locale-safe).
- R1: no change (reviewer: harmless, owner_only_file is idempotent).
