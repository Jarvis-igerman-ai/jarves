# JARVIS — ערכת הנחיות חסכונית ל-Claude Code ול-Codex

**מצב הפרויקט:** שלב 1 — בניית תאום דיגיטלי מלא ל-Windows, ללא רכישת חומרה וללא תנועה מכנית.

## איך להתחיל
1. חלץ את ה-ZIP לתיקיית Repository חדשה, פתח אותה ב-Cursor / VS Code.
2. עבוד עם **סוכן אחד בלבד** בכל פעם. ב-Claude Code או Codex כתוב: `Read AGENTS.md and docs/NOW.md. Execute only the active task, propose a plan first, then stop after one focused verification.`
3. לפני שינוי ראשון, הסוכן יציג תוכנית קצרה (עד 5 צעדים), קבצים ותנאי סיום. אם היא חורגת — אל תאשר.
4. בסיום קרא `docs/HANDOFF.md`. רק לאחר אישורך מקדמים ל-task הבא.

## מה קוראים ומתי
- **תמיד:** `AGENTS.md` + `docs/NOW.md`.
- **בעת הצורך בלבד:** `docs/CONTEXT_MAP.md` שמצביע לחוזה הספציפי.
- **לא קוראים אוטומטית:** `docs/archive/` או `archive/legacy/` (ידע רקע, תוכנית אב ישנה, סימולטור ROBI קודם).
- `CLAUDE.md` הוא הפניה קצרה, לא מסמך הוראות כפול.

## מה אנחנו בונים עכשיו
מחשב Windows מציג JARVIS תלת-ממדי ריאליסטי, שמקור המידות שלו ב-FreeCAD, הגימור החזותי ב-Blender והאינטראקציה ב-Godot. מערכת הליבה (Python) רואה אותן פקודות ואירועים בין מדמה כפתור/GPIO, מצלמה, מיקרופון, רמקולים וחיישנים, ובהמשך חומרה אמיתית. **כל שלב נבנה ומאושר בנפרד**. אין כוונה לטעון שכל תנאי האקוסטיקה/חשמל/התאמה לייצור מדומים 1:1.

## ההחלטות שהכי קל לפספס
- השם הוא **JARVIS**, לא ROBI (השם הישן מופיע רק בארכיון).
- כרגע **אין תנועה מכנית**, Servo, ESP32 למנועים או Webots.
- Godot הוא הבחירה הנוכחית לסימולטור והפנים; על Raspberry Pi טרם אומתה מהירות מספקת, ויש fallback נקודתי ללא שכתוב Core.
- בהמשך **אודיו ומצלמה אמיתיים ייבדקו קודם על Windows** בחיבור USB, ורק אחר כך יועברו ל-Linux ברובוט.
- אין סיבה לקנות Raspberry Pi / הדפסות / הרחבות AI לפני אישור סימולטור ובדיקות רכיבים.

## קבצים עיקריים
`docs/NOW.md` משימה פעילה • `docs/CONTEXT_MAP.md` אילו קבצים מותר לפתוח • `docs/ARCHITECTURE.md` חלוקת שכבות • `docs/DEVICE_CONTRACT.md` אירועים • `docs/FACE_RUNTIME.md` אותה תצוגת פנים • `docs/HANDOFF.md` דוח קצר.

הקבצים המפורטים ב-`docs/archive/` שומרים את כל החלטות החומרה, הסקופ והמעבר הפיזי — לא חלק מה-context הרגיל.
